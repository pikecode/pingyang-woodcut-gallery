## 1. 自动构建（GitHub Actions）

每次向 `main` 分支推送代码，CI 会自动并行构建 macOS 和 Windows 安装包。

**触发条件：**
- `desktop/**` 或 `h5/public/**` 有变动时自动触发
- 或在 GitHub Actions 页面手动触发（可选择是否创建 Release）

**下载安装包：**
GitHub → 仓库 → Actions → 对应 run → 底部 **Artifacts**

| Artifact | 内容 |
|---|---|
| `pingyang-macos` | macOS `.dmg` 安装镜像 |
| `pingyang-windows-msi` | Windows `.msi` 安装程序（推荐） |
| `pingyang-windows-exe` | Windows `.exe` NSIS 安装程序 |

> Artifacts 保留 **14天**，超期自动删除。如需永久保存，用 `workflow_dispatch` 触发并选择 `release=true`，会创建草稿 Release。

## 2. macOS 安全警告（Gatekeeper）

### 问题说明

未经 Apple 签名/公证的 `.app` 文件，macOS 会弹出「无法打开，因为无法验证开发者」的提示，并阻止启动。

### 方案A：右键绕过（免费，立即可用）

适合内部演示、馆方自用场景。

**方法1：右键菜单**
1. 将 `.app` 拖到「应用程序」文件夹
2. **右键点击** `.app` 图标
3. 选择「**打开**」
4. 弹窗中再点「**打开**」
5. 此后即可正常双击启动

**方法2：终端命令**
```bash
xattr -cr /Applications/PingyangGallery.app
```
执行一次即可，之后正常使用。

**方法3：系统设置**
1. 双击尝试打开（会报错）
2. 打开「系统设置」→「隐私与安全性」
3. 滚动到底部，点击「**仍要打开**」按钮

---

### 方案B：ad-hoc 签名（免费，减少提示）

不需要 Apple 开发者账号，本地对 `.app` 进行自签名：

```bash
# 下载 .dmg，挂载后找到 .app
codesign --deep --force --sign - /Applications/PingyangGallery.app
```

或在 GitHub Actions 中自动添加（更新 workflow 文件）。效果：安全警告次数减少，但首次仍需方案A 的右键操作。

---

### 方案C：Apple 开发者证书 + 公证（$99/年，彻底解决）

适合对外公开分发场景。

**步骤概览：**

1. 注册 [Apple Developer Program](https://developer.apple.com/programs/)（$99/年）
2. 在 Xcode 或开发者后台创建 **Developer ID Application** 证书
3. 导出 `.p12` 证书文件，记录密码
4. 在 GitHub 仓库 Settings → Secrets 添加：
   - `APPLE_CERTIFICATE`（base64 编码的 .p12）
   - `APPLE_CERTIFICATE_PASSWORD`（.p12 密码）
   - `APPLE_SIGNING_IDENTITY`（证书名，如 `Developer ID Application: xxx`）
   - `APPLE_ID`（Apple 账号邮箱）
   - `APPLE_PASSWORD`（App 专用密码）
   - `APPLE_TEAM_ID`（Team ID，在开发者后台查看）
5. 更新 `tauri.conf.json` 或 CI workflow 启用签名和公证
6. 构建后用户下载 → 无任何安全提示，直接打开

**在 `tauri.conf.json` 添加签名配置：**
```json
"bundle": {
  "macOS": {
    "signingIdentity": "$APPLE_SIGNING_IDENTITY",
    "providerShortName": "$APPLE_TEAM_ID",
    "entitlements": null
  }
}
```

## 3. Windows 安全提示（SmartScreen）

未签名的 Windows exe/msi 会触发 SmartScreen 警告「Windows 已保护你的电脑」。

**绕过方法：**
1. 弹出 SmartScreen 警告时，点击「**更多信息**」
2. 点击「**仍要运行**」

**彻底解决：** 购买代码签名证书（EV 证书约 $200–400/年），在 CI 中配置 Windows 签名。

## 4. 本地手动打包

如需在本地机器打包而非 CI，执行：

```bash
# macOS
cd desktop
npm run tauri build
# 输出：desktop/src-tauri/target/release/bundle/dmg/PingyangGallery_0.1.0_x64.dmg

# Windows（在 Windows 机器上）
cd desktop
npm run tauri build
# 输出：desktop\src-tauri\target\release\bundle\msi\PingyangGallery_0.1.0_x64_en-US.msi
```

> **前提：** 需要安装 Rust 工具链（`rustup`）。参见 [docs/项目结构与规划总览.md](./项目结构与规划总览.md) 中的安装说明。

## 5. 常见构建错误

| 错误 | 原因 | 解决方案 |
|---|---|---|
| `icons/icon.ico not found` | Windows 需要 .ico 图标 | 确认 `icons/icon.ico` 已提交且在 `tauri.conf.json` 的 `bundle.icon` 中引用 |
| `failed to run light.exe` | 产品名含中文导致 WiX 路径错误 | `productName` 使用 ASCII 字符 |
| `Couldn't find a .ico icon` | 同上，WiX 找不到 .ico | 在 `bundle.icon` 数组中加入 `"icons/icon.ico"` |
| macOS 「无法验证开发者」| 未签名 | 参见本文第 2 节 |
| Windows SmartScreen 警告 | 未签名 | 参见本文第 3 节 |
