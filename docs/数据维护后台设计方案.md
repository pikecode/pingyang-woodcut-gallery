# 数据维护后台设计方案

## 目标

为正式数据提供一个本地维护页面，方便后续查看、核对、修改：

- 标题；
- 类别；
- 内容说明；
- 图片核对备注；
- 来源文档定位；
- 新旧标题不同、尺寸缺失等待核对问题。

维护页面不进入普通展览流程，需要通过隐藏入口访问。

## 维护数据结构

程序展示和维护的核心字段：

| 字段 | 含义 | 是否用于展示 |
|---|---|---|
| `title` | 标题 / 作品名称 | 是 |
| `category` | 类别 | 是 |
| `content` | 内容说明 | 是 |
| `images` | 图片 | 是 |
| `sourceRef` | 文字来源文档和第几条 | 维护核对 |
| `imageSourceRef` | 图片来源文档和第几条 | 维护核对 |

辅助字段：

| 字段 | 用途 |
|---|---|
| `slug` | 稳定 ID |
| `officialNo` | staging 全局序号 |
| `sameTitleGroup` | 同题作品关系 |
| `issues` | 待核对问题 |
| `sourceFields` | 原始字段保留 |
| `imageReviewNote` | 图片调整备注，维护页新增 |
| `maintenanceNote` | 人工维护备注，维护页新增 |

## 数据来源

文字以校正后的修订版文档为准：

```text
/Users/ompeak/Desktop/aaa/20260803修订版木版年画
```

图片以高清旧文档为准：

```text
/Users/ompeak/Desktop/aaa/平阳木版年画
```

维护页前端数据：

```text
desktop/public/data/official-artworks.json
desktop/public/data/official-import-report.json
desktop/public/official-images/
```

正式原图仍保留在：

```text
assets/official-originals/
```

`desktop/public/official-images/` 是维护页预览图，由正式原图生成，可重复构建。

## 入口设计

维护页不显示在普通 UI 中。

访问方式：

1. 隐藏点击入口：

```text
连续点击“平阳木版年画 · 博观集”品牌标题 3 下
```

分类首页和藏品列表页都支持。

2. URL hash：

```text
#maintenance
```

3. 快捷键：

```text
Ctrl + Alt + E
```

进入后需要入口码：

```text
pingyang-admin
```

说明：这个入口码是本地维护门禁，不是强安全认证。它的目的只是避免普通展示时误进入维护页。

## 当前维护页能力

已实现：

- 221 条正式数据列表；
- 按标题、类别、来源搜索；
- 按类别筛选；
- 按“有待核对 / 无待核对”筛选；
- 图片预览和多图缩略图；
- 显示文字来源 `sourceRef`；
- 显示图片来源 `imageSourceRef`；
- 显示待核对项；
- 编辑标题；
- 编辑类别；
- 编辑内容说明；
- 记录图片调整备注；
- 记录维护备注；
- 保存到本机草稿；
- 导出变更包；
- 导出合并预览 JSON；
- 重置单条记录。

## 生效机制

当前采用“本机草稿 + 展示页实时合并”的机制：

```text
localStorage: pingyang.maintenance.overrides.v1
```

保存后：

- 当前维护页立即生效；
- 普通展览页立即生效；
- 刷新页面后仍保留；
- 可导出 `official-artwork-overrides.json`；
- 可导出 `official-artworks-merged-preview.json`。

实现方式：

- 普通展览页加载 `desktop/public/data/official-artworks.json`；
- 再合并本机草稿 overrides；
- 维护页每次保存都会发出 `pingyang:gallery-overrides-updated` 事件；
- 展览页监听该事件并即时刷新展示数据。

注意：这里的“立即生效”指 Desktop 当前应用展示立即生效，不代表已经写回源 Word 文档或 staging JSON。

这样做的原因：

- 不直接覆盖正式 staging 数据；
- 不直接改原始文档；
- 所有人工修改都有明确变更包；
- 出错可以清理本机草稿或重置单条。

## 后续升级方向

如果确认维护页要把修改固化到项目文件，建议增加 Tauri 落盘能力：

1. 新增 Tauri command：

```text
save_official_overrides
load_official_overrides
```

2. 写入：

```text
data/staging/official-overrides.json
```

3. 构建正式数据时合并：

```text
official-artworks.json + official-overrides.json
```

4. 所有修改仍然不直接改源 Word 文档，而是作为结构化修订层保存。

这个方案比直接改 `official-artworks.json` 更稳，因为导入脚本可以反复重跑，人工修订不会丢。
