## 1. 执行摘要

当前开发重心已经切换到 Desktop，H5 和小程序暂停维护。桌面端是独立交付产品，核心价值在于：

- **高清全屏展示**：桌面大屏下年画的细节呈现远优于手机
- **本地原图直达**：可直接读取本地 `assets/originals/`（438 MB 原始图档），无需 CDN
- **离线完整运行**：馆方内部演示、无网络环境下展览均可用
- **专业操作体验**：键盘快捷键、窗口管理、批量导出、打印目录

## 2. 技术方案对比

### 2.1 主流方案

| 维度 | Electron | Tauri | Flutter Desktop | 原生 (Swift/WPF) |
|---|---|---|---|---|
| 代码复用 | ★★★ 直接复用 H5 React 代码 | ★★★ 复用 H5 React 代码 | ★ 须重写 | ✗ 各平台独立 |
| 安装包大小 | 150–200 MB | 5–15 MB | 30–60 MB | 10–30 MB |
| 内存占用 | 高（自带 Chromium） | 低（用系统 WebView） |中等 | 低 |
| 原生能力 | Node.js IPC 访问 | Rust 指令 + 安全沙箱 | 原生渲染 | 完整 |
| 动画 / GSAP | 完全兼容 | 完全兼容 | 不适用 | 不适用 |
| 开发成本 | 低（JS/TS 全栈） | 低前端 + 中等 Rust | 高（Dart） | 高 |
| 跨平台 | macOS/Win/Linux | macOS/Win/Linux | 全平台 | 有限 |
| 生态成熟度 | 成熟（VSCode、Slack） | 新兴但稳定 | 成熟 | 平台绑定 |

### 2.2 推荐方案：**Tauri**

**理由：**
1. React + Vite 前端开发效率高，同时保留独立的桌面交互和资产边界
2. 安装包体积仅 5–10 MB（Electron 约 150 MB），对馆方分发友好
3. Rust 后端提供安全的文件系统访问——可直接读取本地原始图档
4. 安全沙箱：渲染进程无法直接访问 Node.js，降低 XSS 风险
5. 内存占用低，适合长时间展览机部署

**Electron 作为备选方案**，当团队无 Rust 经验时可优先选择，前期开发成本更低。

## 3. 工程架构

```
pingyang-woodcut-gallery/
├── h5/              # 历史 H5（暂停维护）

├── desktop/         # 当前主项目
│   ├── public/      # 独立 WebP 和 artworks.json
│   ├── src-tauri/   # Rust 后端

│   │   ├── App.jsx
│   │   ├── styles.css
│   │   └── main.jsx
│   ├── index.html
│   ├── vite.config.ts
│   └── package.json
├── data/            # 共用数据
├── docs/            # 共用文档
└── assets/          # 原始图档
```

### 3.2 前端与资产策略

Desktop 不再从 `h5/public` 读取运行资产。标准数据从根目录 `data/exports` 生成到
`desktop/public`，原图通过用户选择的外部 `assets/originals` 文件夹读取：

```ts
const bytes = await invoke('read_local_image', {
  originalPath: image.originalPath,
  libraryRoot,
```

## 5. 开发阶段规划

### 阶段一：脚手架搭建（已完成）

```bash
cd desktop
npx create-tauri-app .  # 选择 React + TypeScript + Vite
```

- 初始化 Tauri 工程
- 复制 H5 前端代码为基础
- 验证构建：`npm run tauri dev`

### 阶段二：布局适配（已完成）

- 宽屏响应式布局（断点 1280px+）
- 窗口最小尺寸限制（1024 × 768）
- 侧边栏 + 主内容区双栏布局（藏品页）
- 全屏模式切换

Rust 后端注册命令：


## 6. 平台发布计划

| 平台 | 打包格式 | 备注 |
|---|---|---|
| macOS | `.dmg` / `.app` | 需要 Apple 开发者证书用于公证 |
| Windows | `.msi` / `.exe` | 可打包为安装程序 |
| Linux | `.AppImage` / `.deb` | 展馆服务器/信息亭多为 Ubuntu |

Tauri 的 `tauri build` 命令在各平台上自动打包对应格式，CI 可配置跨平台构建。

## 9. 当前结论

桌面端已经采用 **Tauri + React 独立实现方案**：

- `desktop/public` 已独立，不依赖暂停维护的 H5
- 20 MB WebP 随安装包离线使用，438 MB 原图由外部目录按需加载
- Rust 命令限制清单路径和图片扩展名，TIFF 只在内存中生成预览
- GSAP 门扉动画、搜索筛选、详情查看器和键盘操作已经实现

下一阶段重点是 macOS/Windows 安装包实机验收、签名公证、打印/PDF 和展览模式。
