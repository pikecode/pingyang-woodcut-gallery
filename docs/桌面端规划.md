# 平阳木版年画数字画廊：桌面端程序规划

> 文档状态：Review Draft  
> 整理日期：2026-07-23  
> 适用范围：桌面端技术选型、架构设计与开发阶段规划

---

## 1. 执行摘要

当前已有两端产品：H5（React + Vite）和小程序（Taro）。桌面端是第三端，核心价值在于：

- **高清全屏展示**：桌面大屏下年画的细节呈现远优于手机
- **本地原图直达**：可直接读取本地 `assets/originals/`（438 MB 原始图档），无需 CDN
- **离线完整运行**：馆方内部演示、无网络环境下展览均可用
- **专业操作体验**：键盘快捷键、窗口管理、批量导出、打印目录

## 2. 技术方案对比

### 2.1 主流方案

| 维度 | Electron | Tauri | Flutter Desktop | 原生 (Swift/WPF) |
|---|---|---|---|---|
| 代码复用 | ★★★ 直接复用 H5 React 代码 | ★★★ 复用 H5 React 代码 | ★ 须重写 | ✗ 各平台独立 |
| 安装包大小 | 150–200 MB | 5–15 MB | 30–60 MB | 10–30 MB |
| 内存占用 | 高（自带 Chromium） | 低（用系统 WebView） |中等 | 低 |
| 原生能力 | Node.js IPC 访问 | Rust 指令 + 安全沙箱 | 原生渲染 | 完整 |
| 动画 / GSAP | 完全兼容 | 完全兼容 | 不适用 | 不适用 |
| 开发成本 | 低（JS/TS 全栈） | 低前端 + 中等 Rust | 高（Dart） | 高 |
| 跨平台 | macOS/Win/Linux | macOS/Win/Linux | 全平台 | 有限 |
| 生态成熟度 | 成熟（VSCode、Slack） | 新兴但稳定 | 成熟 | 平台绑定 |

### 2.2 推荐方案：**Tauri**

**理由：**
1. 复用现有 H5 的 React + Vite 代码，前端几乎不重写
2. 安装包体积仅 5–10 MB（Electron 约 150 MB），对馆方分发友好
3. Rust 后端提供安全的文件系统访问——可直接读取本地原始图档
4. 安全沙箱：渲染进程无法直接访问 Node.js，降低 XSS 风险
5. 内存占用低，适合长时间展览机部署

**Electron 作为备选方案**，当团队无 Rust 经验时可优先选择，前期开发成本更低。

## 3. 工程架构

### 3.1 在现有 Monorepo 中新增 `desktop/`

```
pingyang-woodcut-gallery/
├── h5/              # React + Vite H5
├── miniapp/         # Taro 小程序
├── desktop/         # Tauri 桌面端（新增）
│   ├── src-tauri/   # Rust 后端
│   │   ├── src/main.rs
│   │   ├── Cargo.toml
│   │   └── tauri.conf.json
│   ├── src/         # 前端（复用 h5/src，或独立定制）
│   │   ├── App.tsx
│   │   ├── styles.css
│   │   └── main.tsx
│   ├── index.html
│   ├── vite.config.ts
│   └── package.json
├── data/            # 共用数据
├── docs/            # 共用文档
└── assets/          # 原始图档
```

### 3.2 前端代码复用策略

H5 项目的核心组件可直接复制到 `desktop/src/`，差异处通过环境变量区分：

```ts
const IS_DESKTOP = typeof window.__TAURI__ !== 'undefined'

// 桌面端：通过 Tauri API 加载本地原图
// H5：使用 /images/ 路径
const imgSrc = IS_DESKTOP ? await invoke('get_image_path', { slug }) : artwork.images[0].path
```

## 4. 桌面端专有功能规划

### 4.1 P0 核心功能（与 H5 等价）

| 功能 | 实现方式 |
|---|---|
| 首页 + 门扉动画 | 直接复用 H5 代码，GSAP 完全兼容 |
| 藏品分类浏览 | 复用，调整布局为宽屏双栏 |
| 搜索 | 复用 |
| 作品详情弹层 | 升级为全屏展示模式 |
| 键盘导航 | 方向键翻页（已有），增加 `F` 全屏 |

### 4.2 P1 桌面增强功能

| 功能 | 说明 |
|---|---|
| **本地原图查看** | 通过 Tauri FS API 读取 `assets/originals/`，呈现438MB 原始高清图 |
| **全屏沉浸模式** | F键或菜单切换，标题栏隐藏，图片铺满屏幕 |
| **原生菜单栏** | 文件（导出）/ 查看（全屏、缩放）/ 帮助 |
| **窗口吸附** | 分屏时展示两件作品对比 |
| **打印目录** | 按题材生成 PDF 图录，调用系统打印对话框 |

### 4.3 P2 运营能力

| 功能 | 说明 |
|---|---|
| **展览模式** | 自动轮播，适合展馆触屏大屏 |
| **批量导出** | 将选中藏品导出为 ZIP（图片 + 说明 JSON） |
| **离线数据更新** | 将新版 `artworks.json` 拖入即可更新馆藏 |

## 5. 开发阶段规划

### 阶段一：脚手架搭建（约 3 天）

```bash
cd desktop
npx create-tauri-app .  # 选择 React + TypeScript + Vite
```

- 初始化 Tauri 工程
- 复制 H5 前端代码为基础
- 验证构建：`npm run tauri dev`

### 阶段二：布局适配（约 5 天）

- 宽屏响应式布局（断点 1280px+）
- 窗口最小尺寸限制（1024 × 768）
- 侧边栏 + 主内容区双栏布局（藏品页）
- 全屏模式切换

### 阶段三：本地原图接入（约 3 天）

Rust 后端注册命令：

```rust
// src-tauri/src/main.rs
#[tauri::command]
fn get_local_image(slug: &str, role: &str) -> Result<Vec<u8>, String> {
    // 读取 assets/originals/{slug}/{role}.jpg 等
}
```

前端通过 `invoke` 调用，显示本地原始高清图。

### 阶段四：增强功能（约 5 天）

- 原生菜单（macOS 风格 / Windows 风格）
- 打印/PDF 导出（调用 `window.print()` + 自定义 print CSS）
- 键盘快捷键完善
- 系统通知（数据更新提示）

## 6. 平台发布计划

| 平台 | 打包格式 | 备注 |
|---|---|---|
| macOS | `.dmg` / `.app` | 需要 Apple 开发者证书用于公证 |
| Windows | `.msi` / `.exe` | 可打包为安装程序 |
| Linux | `.AppImage` / `.deb` | 展馆服务器/信息亭多为 Ubuntu |

Tauri 的 `tauri build` 命令在各平台上自动打包对应格式，CI 可配置跨平台构建。

## 9. 当前结论

桌面端推荐选用 **Tauri + React 复用方案**，原因是：

- 前端代码 80% 直接复用，开发周期最短
- 安装包 < 10 MB，适合馆方低带宽分发
- 本地原图直读是桌面端独有的核心价值，Tauri 的 Rust FS API 是最安全的实现方式
- GSAP 动画、门扉开场等已有效果无需任何修改

主要不确定因素是团队是否具备 Rust 基础，若完全没有，可以先用 Electron 验证产品逻辑，后续迁移 Tauri。
